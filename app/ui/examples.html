API Examples

How to call the local APIs from C#, JavaScript and cURL. ← back to console · OpenAPI docs

Base URL is http://localhost:8000 (change host/port for a remote server). No authentication is required by default. All endpoints accept multipart/form-data; options are passed as query-string parameters.

Transcribe a call

POST /voice/transcribe

Upload an audio file (WAV/MP3/M4A/FLAC/OGG). Returns the diarized transcript.

fileform field — the audio file (required)
num_speakersknown speaker count, e.g. 2; omit/-1 for auto (ignored for dual-channel)
languageforce ISO code e.g. de, fr; omit to auto-detect
thresholddiarization sensitivity 0–1 (mono only)
diarization_modeauto | channel | cluster

Analyze a call (post-call)

POST /voice/analysis

Send either an audio file (it is transcribed first) or a transcript JSON string from /voice/transcribe (skips re-transcribing). Returns transcript + analysis (metrics, acoustic voice features, and LLM insights).

fileaudio file (use this OR transcript)
transcriptform field — a transcript JSON string (use this OR file)
output_languageresult language; default de; 'auto' matches the call

Detect faces

POST /face/detect

Upload an image; returns bounding boxes (largest-first).

Compare two faces

POST /face/compare

Upload two images; returns cosine similarity and a match decision.

file1, file2the two images (required)
thresholdmatch threshold 0–1 (default 0.40)

Live / near-real-time streaming (roadmap — not yet implemented)

The current pipeline is batch (whole file). The sketch below shows the intended WebSocket design for live transcription. It does not work against the current build — it is here to illustrate the future approach.

Real-time needs a streaming-capable model (faster-whisper is offline/batch). Options that stay open-source & offline: sherpa-onnx online (streaming Zipformer) — same library we already use, lowest latency on CPU; or whisper-streaming / WhisperLive — wraps Whisper with a chunk + "local agreement" policy for higher accuracy at ~2–4s latency. For dual-channel calls, each party is a separate stream, so live diarization is free. LLM analysis stays post-call.
